# 🚀 CI/CD Pipeline Documentation

Этот репозиторий использует GitHub Actions для автоматической сборки Docker-образов и их безопасного развертывания на удаленном сервере.

Процесс разделен на **два независимых пайплайна**:
1. **Build & Push** — сборка кода и публикация образов в GitHub Container Registry (GHCR).
2. **Deploy** — доставка готовых образов на сервер через Ansible.

---

## 🏗 Архитектура и Ветки

Проект использует разделение кода и инфраструктуры:

| Ветка | Что содержит | Для чего используется |
| :--- | :--- | :--- |
| **`main`** | Исходный код, `Dockerfile`, `docker-compose.yml`, `docker-compose.prod.yml` | Основная ветка разработки. Отсюда берется код для сборки образов. |
| **`pipelines`** | `.github/workflows/`, `ansible/`, `scripts/` | Ветка с инфраструктурой. Пайплайны запускаются отсюда. |

> **Важно:** Пайплайны лежат в ветке `pipelines`, но собирают и деплоят код из ветки, которую вы укажете при запуске (по умолчанию — `main`).

---

## 📦 Пайплайн 1: Build & Push (Сборка)

**Файл:** `.github/workflows/build-push.yml` (в ветке `pipelines`)
**Цель:** Собрать образы и отправить их в Registry.

### Как это работает
1. Пайплайн берет код из ветки, указанной в поле `app_ref` (по умолчанию `main`).
2. Собирает 3 Docker-образа: `api`, `worker`, `frontend`.
3. Присваивает им два тега: `latest` и короткий SHA коммита (например, `f06a1fc`).
4. Пушит их в **GitHub Container Registry**.

### Как запустить
1. Перейдите в **Actions** → **Build and Push Images**.
2. Нажмите **Run workflow**.
3. Укажите ветку `pipelines` (откуда запускаем) и `app_ref` (какую ветку кода собирать, обычно `main`).
4. После завершения скопируйте **SHA коммита** из логов (он понадобится для деплоя).

---

## 🚢 Пайплайн 2: Deploy (Деплой)

**Файл:** `.github/workflows/deploy.yml` (в ветке `pipelines`)
**Цель:** Скачать готовые образы на сервер и запустить их.

### Как это работает
1. Пайплайн поднимает **WireGuard** для доступа в закрытую сеть.
2. Устанавливает SSH-соединение с сервером.
3. **Ansible** выполняет следующие шаги:
   * Обновляет файлы на сервере (`git pull` из `main`).
   * Создает файл `.env` (в него записываются секреты и тег образа).
   * Авторизуется в GHCR.
   * Скачивает образы (`docker compose pull`).
   * Перезапускает контейнеры (`docker compose up -d`).

### Как запустить
1. Перейдите в **Actions** → **Deploy**.
2. Нажмите **Run workflow**.
3. Заполните параметры:
   * **`app_ref`** — ветка кода для обновления файлов на сервере (обычно `main`).
   * **`image_tag`** — SHA коммита из предыдущего шага (например, `f06a1fc`). Это гарантирует, что запустится именно та версия, которую вы собрали.
4. Нажмите **Run workflow**.

## 🔐 Секреты и переменные

Все чувствительные данные хранятся в **GitHub Environment** (называется `sbshinobi`).

| Имя секрета | Назначение |
| :--- | :--- |
| `WG_ENDPOINT` | Публичный IP и порт WireGuard-сервера. |
| `WG_PEER_PUBLIC` | Публичный ключ WireGuard-сервера. |
| `WG_ADDRESS` | Внутренний IP-адрес раннера в сети WireGuard. |
| `WG_ALLOWED_IPS` | Подсети, которые маршрутизируются через VPN. |
| `WG_PRIVATE_KEY` | Приватный ключ клиента WireGuard. |
| `OPENSSH_PRIVATE_KEY` | SSH-ключ для доступа к серверу. |
| `APP_ENV` | Содержимое файла `.env` (пароли к БД, ключи API и т.д.). |
| `GHCR_USER` | Ваш GitHub-логин (для скачивания образов). |
| `GHCR_TOKEN` | Personal Access Token (с правом `read:packages`). |

## 🗂 Структура репозитория

### Ветка `main` (Код)
| Файл | Описание |
| :--- | :--- |
| `Dockerfile` | Инструкция для сборки `api` и `worker`. |
| `frontend/Dockerfile` | Инструкция для сборки `frontend`. |
| `docker-compose.yml` | Базовый конфиг (для локальной разработки). |
| `docker-compose.prod.yml` | Оверрайд для сервера (использует образы из GHCR). |
| `.dockerignore` | Исключает `.env`, `.git` и мусор из сборки. |

### Ветка `pipelines` (Инфраструктура)
| Файл | Описание |
| :--- | :--- |
| `.github/workflows/build-push.yml` | Пайплайн сборки. |
| `.github/workflows/deploy.yml` | Пайплайн деплоя. |
| `ansible/deploy.yml` | Плейбук для настройки сервера. |
| `ansible/inventory.yml` | Список серверов (IP, пользователь). |
| `scripts/wireguard-up.sh` | Скрипт поднятия VPN на раннере. |
